# V10 单腿 IK 双分支纯计算交接（2026-09-29）

用户决定以已组装的 Structure V10 机械中位为准：八路保存的舵机名义90°，照片一条腿大腿竖直向下、小腿向左水平，小腿驱动舵机壳体固定在大腿。不能把 Controller V4 手册的 V7 装配照片当 V10 机械零位。上游软件参考 `third_party/py-apple-servo/software/py-apple-dynamics/Py Apple Dynamics V7.3 SRC/PA-Dynamics V7.3/PA_IK.py`、`padog.py`；现行 C++ 在 `mechanical_dog/src/Ctrl/Applepy8Dof.cpp`。

用户的图中两角均为**几何角**：θ₁ 是大腿与所选水平轴，θ₂ 是两杆方向折转角（膝内角为180°−θ₂），都不是伺服电气角。`shank_deg=acos((d²−a²−b²)/(2ab))` 与图片及上游相符。旧髋角仅取镜像坐标下 `φ−δ`；新增显式 `IkBendBranch::OppositePlus` 求 `φ+δ`，并在 `LegIkAngles` 保留 branch。以**仅供示意**的 V7 名义轴距 `a=80,b=69 mm`、照片中位足端 `(-69,-80) mm`，双支路分别给髋内部角约 `8.444°` 与 `90°`，膝折转均为 `90°`，测试 FK 均回代到同一足端。新支路的角度不得由旧 `toServoAngles` 直接转为 PWM，因此该函数显式拒绝它且不改输出。原 `C(q)=0.006649q²+0.4414q+5.53` 在膝折转90°时为 `99.1129°`，无法自然通过当前保存的伺服90°中位；V10 动态连杆斜率及四腿符号仍未知。

默认网页预览/`MotionController` 仍使用旧 V7.3 支路；网页现在直接警示这不是 V10 可执行解算。`Board::kV10MotionKinematicsConfirmed=false` 新增独立门槛，与接线/逐关节限位确认共同锁定实机运动；**将来不能仅翻成 true，须先替换 MotionController 的 V7 Servo 映射并验证四腿 V10 模型**。本轮未上传、未连接硬件、未发送 PWM。

主机严格编译/运行 `test/host/host_tests.cpp` 与 `test/host/motion_tests.cpp` 通过；Node 网页烟雾通过；PlatformIO `esp32-c3-devkitc-02` 固件构建通过。独立只读数学/安全审核 PASS，范围仅限“双支路纯计算且未连接实机”；不证明 V10 长度、连杆运动曲线或机械安全。下一步先确认 V10 髋-膝/膝-足轴距及每腿折叠/镜像方向，然后在纯计算层建立 V10 连杆映射和中位锚点、做多点单调与全周期主机预检，再讨论硬件有限动作。现成 `0.4.0` 步态编译成功不是本板可走证据。
