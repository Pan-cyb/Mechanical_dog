# 2026-09-28 Applepy_v1 单路关闭与中位保存说明

## 用户需求与现场版本

用户询问网页“关闭输出后保存中位”的含义，并要求增加“关闭特定通道”。当前工作区候选 `mechanical_dog/` 已更新至 `0.3.6`；**没有上传 COM4、没有在 PCA9685/MG90 上实测**。板上最后经串口确认的仍是 `0.3.4`（3 秒自动超时），前一版 `0.3.5` 手动保持候选亦未烧录。参考[手动保持记录](2026-09-28_manual-servo-hold.md)了解取消超时后的风险。

## 中位到底保存了什么

网页 ±1° 微调的是**所选物理接口**的名义中位角（初值 90°、名义 1500 µs），每次修改当前 RAM 中的角度并立即向该路发送相应 PWM；它并不测量舵机轴的实际角度，也不是“回中位”。“保存所选中位”才调用 `Preferences` 将这一路当前中心角写入 ESP32 NVS，供重启后读取，**按钮本身既不关闭输出，也不发舵机脉冲**。`ChannelCalibration::save` 继续要求全局 `off` 已解除 ARM、无 PCA 故障；单路关闭成功后虽然停止该路，仍保持 ARM，所以保存按钮仍禁用。用户可单路暂停后继续测试，最终点“关闭全部输出”再决定是否保存；不保存的微调在重启后丢失。

## 单路关闭的实现和边界

- `IServoPwm` 增 `offChannel(ch)`；`Pca9685` 对 `0≤ch<16` 且已就绪时仅向 LEDn_OFF_H (`0x09+4×ch`) 写 `0x10`（FULL_OFF），如 ch0=0x09、ch8=0x29，**不写**广播全关寄存器 `0xFD`，不改其他通道的寄存器。NXP PCA9685 手册 `.work/PCA9685_datasheet.pdf` PDF 第 24 页给出 LEDn_OFF_H bit4 的 FULL_OFF 语义；当前板控制 50 Hz，通道许可池仍只有 `{0,1,2,3,8,9,10,11}`。
- `ServoController::offChannel` 只接受**当前活动通道**；选错/无活动时拒绝且不访问总线，避免另一条仍输出却显示成功。成功后只清活动通道/脉宽记录，ARM 保持，可继续发脉宽；若单路 I²C 写失败，尝试 all-off、撤销 ARM 并锁故障。即使软件故障状态已置位，物理 PWM 可能因 I²C 失败继续输出，必须物理切断舵机电源。
- 串口 `off 0` 对应丝印 Servo1/PCA ch0，仅关闭这一活动通道；原精确命令 `off` 仍对 16 路软件全关并退出 ARM。网页 `POST /api/action cmd=off_channel&channel=0` 通过原会话 token 和参数白名单，后端与串口共用 `RobotApp::execute`；“关闭所选通道”仅在当前选择等于活动通道且 PCA/IMU/故障状态允许时启用，任何状态下保留全局关闭按钮。

## 验证及下一步

严格 `g++ -std=c++17 -Wall -Wextra -Werror` 主机回归退出 0：覆盖 `off <ch>` 严格解析、PCA 目标寄存器/字节、关闭 ch0/ch8 不碰别路、无效/非活动通道拒绝、单路关闭保留 ARM、失败锁故障及全局 all-off 尝试、单路关闭后 `save` 拒绝而全局关闭后允许。Node `vm.Script`/网页文案烟雾测试退出 0；PlatformIO `esp32-c3-devkitc-02` 构建成功，`firmware.bin` 约 840.1 KB。测试没有触碰硬件，未验证电源、实际脉宽或真实舵机行为。

只有确认没有舵机接入（先仅示波器），或确认可立即物理切断舵机 V+ 后，才考虑烧录 `0.3.6`。首个硬件切片：手动 ARM→丝印 Servo1 1500 µs→网页“关闭所选通道”/串口 `off 0`，示波器确认 ch0 脉冲消失且 ARM 仍在；再发 ch0 脉冲→全局 `off`，确认全路关闭、ARM 撤销。故障或断网时不可将软件 `off` 视为硬件急停；OE# 固定下拉。
