# Applepy_v1 Wi-Fi 调试 UI 交接（2026-09-26）

## 当前目标与参考

在不正式安装机械腿、不猜测八个关节接线的阶段，提供电脑浏览器优先、USB 串口备用的单路 PCA9685 台架调试和可保存中位的 UI。现行工程为 `G:\PROJECT\Mechanical_dog\mechanical_dog`，硬件依据为仓库根目录 `SCH_Schematic1_2026-09-24.pdf`，不是历史 OQ12 原理图。原项目以 `third_party/py-apple-servo/software/py-apple-dynamics/Py Apple Dynamics V7.3 SRC/PA-Dynamics V7.3/` 中的 `main.py`、`padog.py`、`web_c.py`、`control.html`、`cal.html` 为行为参考；固定提交与 GPL-3.0 许可边界见 [ORIGINAL_PROJECT.md](../ORIGINAL_PROJECT.md)。

## 原项目核对与本次决策

- 原项目确由 ESP32 MicroPython AP + 80 端口 HTTP 提供截图中的标定页。旧 `cal.html` 以 `?key=l1..l4` 选腿，`hi/hd/si/sd` 每次微调一个腿关节中位 1°，`t9` 开始标定会让八路同时输出中位，`sc` 覆写 `config_s.py` 后退出。`web_c.py` 含对 GET 参数执行 `exec()`，**不可原样移植**。源码没有显式 AP 密码；`192.168.4.1` 是截图示例，原代码通过 `ifconfig()` 得到地址。详见 [ORIGINAL_ARCHITECTURE.md](../ORIGINAL_ARCHITECTURE.md)。
- 新板开机启动 `Applepy-Debug` WPA2 SoftAP；电脑连接后访问 `http://192.168.4.1/`，不依赖手机 App 或路由器。密码当前硬编码在 `mechanical_dog/include/Board/DebugWifiConfig.h`（实验室默认 `ApplepyLab-2026`），**分享固件或外场使用前必须修改**。
- Web `GET /api/state` 只读，`POST /api/action` 仅接收 `arm/off/pulse/nudge/save`；页面 token 校验防止不经页面直接误触，但**不是用户认证**。USB 串口 115200 的 `help/status/imu/arm/pwm/nudge/center/off/save/keepalive` 可继续诊断；两路动作共用 `RobotApp::execute` 和台架安全状态。
- 操作对象仅为物理丝印 Servo1–4/9–12，即 PCA 零基 `0..3,8..11`。**腿/关节映射未确认**，所以不提供按腿标定或自动八路回中位。上电、页面加载、ARM、改滑杆、读取中位、状态轮询、NVS 读取均不自动驱动，也不自动 keepalive。
- 单次原始脉宽限定 1000–2000 µs；±1° 按名义 0–180°↔500–2500 µs 对当前单路中位微调，会即时发送脉冲且只更改内存。必须先 `off`，再显式 `save` 选中通道到 NVS；未保存则重启恢复已保存值或默认 90°。`off`、切通道及约 3 秒超时均只是经 I²C 发送软件 all-off。
- 若活动通道上次发的是与当前中位不同的原始脉宽，±1° 会拒绝，须先 `off`/重新 `arm`，以免突然跳转；全关 I²C 失败会锁存故障并拒绝 `save`，不能谎称已安全断输出。

## 风险与下一步

- `WebServer::handleClient()` 为同步处理；即使主循环在处理前后检查软件超时，也不能保证 HTTP 阻塞时的 3 秒关断延迟。页面轮询不会续期；测试时勿把超时视作硬件保护。
- 现行 PCB 上 PCA9685 `OE#` 由 10 kΩ 下拉，没有可由 MCU 控制的硬件急停/舵机电源断开。I²C 卡住或写全关失败时，需要可触及的**物理舵机电源切断**。默认热点口令只用于受控实验室。
- 先不接舵机，确认电源轨与供电路径，用 USB 烧录并检查串口日志；电脑连 AP、打开网页，检查 PCA/IMU 状态，再以示波器核验选定接口单路 50 Hz/1000–2000 µs、3 秒超时及 `off`。之后确认 MG90 额定电压和安全断电，限流测试一只脱离机械负载的舵机及 NVS 保存/重启。确认 H/S→Servo 接线、每只零位/限位后才接入 `Applepy8Dof` 和多路动作。
