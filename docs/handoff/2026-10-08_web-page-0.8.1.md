# 0.8.1 首页空白热修复交接

## 现象与证据

- 用户在ESP32-C3的0.8.0固件上报告首页无法打开，同时确认`/api/state`有效：PCA/IMU ready、`armed=false`、`calibration_samples=100/required=100`、`gyro_calibrated=true`、`attitude_ok=true`，原舵机中位可读。
- 用户没有提供根路径的HTTP响应头抓包；HTTP 200空正文是根据实际库/ELF分析，并由本地忠实模拟当前Arduino `String`限制的旧发送路径回归确认。
- 内嵌UTF-8首页正文为75,507字节，超过当前无PSRAM Arduino ESP32 `String`的65,535容量上限。旧路径先执行`String html = FPSTR(kDebugWebPage)`，复制失败会使`String`失效为空，随后仍发送200。
- 0.8.0的主机与Node UI测试没有运行真实WebServer发送路径，因此未覆盖该容量限制。

## 0.8.1修改

- `FlashWebPageResponse`先确认模板中恰好存在一个`__TOKEN__`，再设置精确`Content-Length`和原有五个响应头。
- 模板前后两段直接从Flash以最多1,024字节调用`sendContent_P`；中间只从RAM写16字节CSRF token。不构造整页`String`、`std::string`、`vector`或等大heap。
- HTML字节、页面功能、POST token校验、动作/IMU/标定/几何/通道/限幅、NVS格式与控制状态机未改。
- 模板缺失、重复或参数非法时在发送前返回500；若传输已开始后共享实现报告失败，只关闭当前客户端，不拼接第二个HTTP响应。当前WebServer的发送API返回`void`，生产适配只能确认已交给client层，不能证明真实网络没有短写。

## 验证

- 旧路径复现：真实75,507字节模板经忠实模拟当前Arduino `String`容量/取整/失效语义后，200正文为空。
- `test/host/run_all_tests.ps1`严格编译与运行exit 0，包含真实中文页、至少128 KB模板、精确Content-Length/字节、唯一token、分块边界、缺失/重复占位符、begin/flash/token写失败停止和重复GET响应一致；原host/gait/motion/body/drive/IK/shank及Node UI回归也全部通过。
- PlatformIO 6.2.0对`esp32-c3-devkitc-02`的detect/list/build均exit 0，未clean、未upload、未列设备。最终`firmware.bin`为1,017,088 bytes，生成时间2026-10-08 21:36:24，SHA-256 `CB5237ED499EAF3B8351C178ED382FEFFEF7D71B983DEBF63995EACE0D988F03`。
