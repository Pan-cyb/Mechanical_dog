# 2026-09-28 IMU 姿态标定现场诊断交接

## 当前目标与重要背景

用户已经烧录 `mechanical_dog/` 的 `0.3.0` 姿态显示固件，网页 Roll/Pitch/Yaw 长时间显示未完成。当前是 ESP32-C3-WROOM-02-H4 + HXY ICM-42688P（I²C `0x19`，ID `0x6A`）+ PCA9685 的 `Applepy_v1`；本轮只发送 `imu/rpy` 查询，没有核对当前是否物理接有舵机。源项目是 `third_party/py-apple-servo` 中 Py-Apple Dynamics V7.3，M0 的 HXY 寄存器实现见 `G:\PROJECT\Electronics Design Contest\the second semester of junior year\M0-chip-package\Myproj\MSPM0G3507_CPP_Template\Legacy\ICM42688\icm42688.c`。这一轮仅处理 IMU 姿态展示与诊断，不把姿态接入闭环或舵机动作。

## 现场证据与原因

- 对实际连接的 `COM4` 做**只读**串口采样：启动报告 PCA9685/IMU ready；数次 `imu` 读数静止且接近 `a=(-0.078,0.845,5.438) m/s²`、`w=(-0.006,0.011,-0.003) rad/s`，对应合量约 `5.504 m/s²` 与 `0.0129 rad/s`；`rpy` 一直 unavailable。这证明 I²C/应用至少在持续输出非零数据，**不证明物理加速度比例正确**。
- 旧 `0.3.0` 的 `Ctrl/AttitudeEstimator.cpp` 要求 100 个连续样本每次均为 `0.9–1.1 g`（约 `8.83–10.79 m/s²`）且角速度合量 `<0.05 rad/s`。现场角速度已低于门槛，然而加速度合量只有约 `5.50 m/s²`，所以校准计数每次归零，网页无角度。每秒网页轮询或同步 HTTP 请求偶发的 40 ms 停顿还会触发旧 `5–30 ms` 采样间隔上限，独立造成无法收满 100 个样本。
- HXY 寄存器地址、`0x0C..0x17` 数据窗口与 `±4 g`、`±1000 dps` 配置和 M0 工程源代码看起来一致；但**真实输出比例为何只相当于约 `0.56 g` 未解决**。可能涉及实际量程、比例解释、器件/装贴、数据窗口或测试姿态，尚不可直接乘 `9.81/5.50` 修正或把偏小合量解释为故障器件。

## 本轮软件改动与验证

- `mechanical_dog/src/Ctrl/AttitudeEstimator.cpp`：将启动加速度绝对 `1 g` 门槛改为静置期间相对稳定的合量参考；保留有限值、基本可信范围 `2.5–20 m/s²` 和 `<0.05 rad/s` 静止角速度检查。标定满 100 个样本后，仅用该次参考判断重力校正是否可信；这是让姿态调试可用的**相对标定**，不是加速度物理量纲校准。
- 同一估计器：消除偶发 `>30 ms` 样本间隔导致启动进度清零的问题，仍要求有效样本至少相隔 5 ms；完成校准后 `>100 ms` 间隔仍会重建姿态及相对 Yaw 零点，保留已求得的陀螺偏置。静止角速度门槛、运动/异常读数处理并未变成安全保证。
- `RobotApp`/网页：版本增至 `0.3.1`，`GET /api/state` 与 UI 新增当前 `calibration_samples`、`calibration_required` 和 `accel_norm_mps2`；串口 `rpy` 在未完成时报告计数/合量，便于现场分辨采样阻滞与数据异常。不改变 `arm`、PWM 或舵机电源安全链。
- 主机测试按**真实调用链** `RobotApp::begin/tick/snapshot`：先加入现场向量，旧实现于 `test/host/host_tests.cpp:563` 断言失败，进程退出码 3；相对合量补丁后此用例通过。再加入每约 40 ms HTTP 阻塞模型，补丁前在该文件约第 586 行断言失败，退出码 3；间隔补丁后现场向量、停顿及组合场景全部通过（`regression_exit=0`）。网页校准进度/合量的 JS 烟雾测试通过。**这些都是主机/模拟接口证据，不等于实板角度验证**。
- 最终 `pio run -e esp32-c3-devkitc-02` 构建成功，`mechanical_dog/.pio/build/esp32-c3-devkitc-02/firmware.bin` 约 `833.3 KB`；主机回归退出码 0、JS 烟雾测试通过。后续代码审查仍应以实际文件/测试输出为准。仓库顶层非 Git 工作树，不能假设存在提交号；旧 `0.3.0` 与此前文档的“待上板”叙述保留为历史快照。
