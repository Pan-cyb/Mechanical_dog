# Applepy_v1 · V10 板级调试技术文档

更新：2026-10-13。适用于`mechanical_dog/`固件`0.8.14`候选，尚未烧录或实机验收。

## 1. 对外接口与操作

ESP32-C3启动SoftAP`Applepy-Debug`，网页入口为`http://192.168.4.1/`；UART0 115200提供同等调试命令。网页和串口可执行Stand、Walk、Trot、单腿测试、Stop/Off、步态参数、姿态/CG、静态平衡、移动CG和方向会话。`GET /`与`GET /api/state`只读，动作通过带页面token的`POST /api/action`白名单进入`RobotApp`。

固件0.8.14保持既有Trot、Walk、body_x范围/默认、trim和Trot Pitch参数。网页把height/Pitch/Roll/body_x合成单个四字段`pose_live_set`请求，150ms debounce且最多一请求在途；固件用候选motion+Profile完整Stand预检后一次提交。OFF只改RAM；协调Stand/Hold复用原1.5s transition，不隐式ARM。height仍由motion NVS保存，Pitch/Roll/body_x仍由Profile保存，schema不变。

方向pad不再使用pointerdown/up。Click开始固定intent并持续150ms renew；切换先`drive_end`并读回新epoch再`drive_begin`。原地踏步仍是`stepping=true`、左右scale0。页面隐藏/renew失败停止本地定时器，MCU 500ms lease到期后保持最后帧；Stop/Off仍走优先重试路径。

只读边界复核固定lift12.8/body_x8/trim.25，覆盖两组中位、五intent和Pitch 0/-0.5°：down114共同step上限18.5，单向前进两Pitch 19.8、Pitch0 24.1；down115共同21.0。输入30mm是参数硬上限，默认17.9不是最新共同极限，down114也不是网页100..115范围内的最大步长最优down。本版不改默认，且软件边界不代表实物稳定。

该offset是开环角度前馈，不是移动IMU闭环。moving CG仍为默认±0.5mm、2mm/s且默认关闭；当前最大步态与其位移包络冲突的只读诊断继续保留在`.work/moving_cg_range_probe_20261010.md`，0.8.11没有扩大范围。

## 2. 硬件与运行环境

目标为ESP32-C3-WROOM-02-H4；GPIO4 SDA/GPIO5 SCL共享100kHz I²C，PCA9685地址`0x40`/50Hz，HXY ICM-42688P地址`0x19`。协调八路顺序为CH0/1/2/3/12/9/10/11。PCA OE#固定下拉，软件Off不是硬件急停；真实试验必须能立即切断舵机V+。

## 3. 目录与模块

- `include/Interface`、`src/Driver`、`src/Port`：设备接口、PCA/HXY驱动、Arduino/Web/NVS适配。
- `src/Ctrl/V10Gait.cpp`：足端轨迹、机身变换、IK、小腿映射与逐帧预检。
- `src/UserApp/RobotApp.cpp`：命令、异步预检、状态机、过渡、调度、平衡、方向租约和故障处理。
- `src/Port/DebugWebPage.h`、`DebugWebServer.cpp`：控制页面与状态JSON。
- `test/host`：假PWM/NVS/IMU、运动学、运动状态机和Node网页回归。

## 4. 控制数据流

命令先进入参数/状态门控；直行请求先由`applyStraightTrim()`生成有效drive intent，再由`V10PreflightCursor`逐帧检查有限数、足端变换、IK、髋窗口、小腿表、0..180°与CG支撑边距。通过后等待新IMU样本，从当前完整帧或八路中位开始1.5s smoothstep过渡；周期运动每20ms生成完整八路命令并顺序写PCA。trim没有反馈闭环，也不恢复速度门限。

零Pitch/Roll时`V10BodyPose`令四腿`forward_out=nominal_forward-body_x`而down不变。`body_x=+8`的物理解读是固定接触足端时机身向机头前移8mm，作用于承重杠杆而非单独压低前脚。原项目`in_y=17`及`X_S/X_goal/tran_mov`也涉及全局X，但其坐标、阶段目标和动态过程不同，当前值不宣称等价。

Profile schema/version不变；合法旧NVS中的0或其他body_x继续优先。缺失、损坏或IO失败才回退+8。固件没有压力、接触、关节位置或实际COM反馈，所以无法由代码证明机器真实重心偏后。

静态平衡和移动CG控制器自己的输出幅值、滤波与slew仍存在，它们是控制算法行为，不是协调舵机速度安全门限。任何运行时几何失败、IMU/ARM丢失、>200ms调度空窗或PCA写失败仍进入保持错误或全关路径。

## 5. 构建与验证

在`mechanical_dog/`执行`test\host\run_all_tests.ps1`。构建使用`build-platformio`技能脚本依次探测、列环境并指定`esp32-c3-devkitc-02`；不要默认clean或upload。本轮产物位于`G:\PROJECT\Mechanical_dog\mechanical_dog\.pio\build\esp32-c3-devkitc-02\firmware.bin`，SHA-256见[交接手册](项目交接手册.md)。

## 6. 限制与风险

没有关节编码器、足端/接触/实际COM反馈；网页角度与足端均为命令模型。未标定的小腿另一侧、机械端点、负载电流、供电裕量、舵机跟随速度和地面稳定性未知。17.9/25.3步长只是当前两组中位×五intent的软件模型边界；持续左偏的根因和最终trim必须实机从小值确认。
