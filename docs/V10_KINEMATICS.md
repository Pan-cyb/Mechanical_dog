## 0.8.11 直行差动默认值

`V10DriveIntent`的原始默认仍为`forward=1, turn=0, stepping=false`。RobotApp用`kDefaultStraightTrim=0.25`调用`applyStraightTrim()`后，普通前进变为`turn=-0.25`，左右scale为`1.00/0.75`；普通倒退变为`turn=+0.25`，左右scale为`-1.00/-0.75`。这只改变左右足端前后轨迹幅值，不改变抬脚曲线、相位、Pitch角或连杆模型。显式左右转与踏步原样通过。

修改前用真实0.8.10模型扫描两组中位、五种intent及Trot Pitch `0/-0.5°`共20个组合，17.9/12.8/0.5/down114/body_x8全部通过完整周期预检。0.8.11没有放宽任何运动学边界。

## 0.8.10 Trot专用Pitch变换

`V10AdvancedMotionParameters::trot_pitch_offset_deg`默认0。`frameDetailed()`只在`mode==Trot`时执行：

\[
pitch_{effective}=pitch_{profile}+pitch_{trot\_offset}
\]

随后把有效Pitch与原有body_x/roll一起送入`V10BodyPose`，再做IK、髋窗口、小腿映射与舵机范围检查。Stand、Walk、Leg和CG Walk不叠加该值，测试以完整帧hash确认输出与offset0一致。有效Pitch须落在−7..+5°；offset自身仍只允许`-0.5..0°`。

真实模型0.1档探测：在`body_x=+8`、两组中位×前/后/左/右/踏步下，`17.9/12.8`配`-0.5°`全过；`17.9/12.9`在phase .250腿1触发`shank_map`。保持13.1mm lift时即使step=0也失败，说明限制来自摆动峰值小腿折转，不能靠减小前后步幅恢复。该补偿是命令角度前馈，不是IMU测得Pitch闭环。

## 0.8.9 步长边界与直行trim

修改前0.8.8代码在`body_x=+8`、两组中位与五intent扫描：Trot共同0.1mm步长上限17.9；18.0在倒退/左转/右转于phase 0.340触发`hip_window`（腿索引0或2），直行前进单独仍可到23.4。Walk共同上限25.3；25.4在非踏步intent于phase 0.040或0.160触发`hip_window`（腿0）。踏步的signed scale为0，所以step输入不改变其前后轨迹；30.1仍由`parametersValid()`拒绝。

直行修正先把名义drive intent变成有效intent，再走原`driveScales()`：

```text
forward > 0, turn≈0: effective_turn = -trim
forward < 0, turn≈0: effective_turn = +trim
left  = clamp(forward - effective_turn)
right = clamp(forward + effective_turn)
```

所以`trim=+0.05`时前进得到`left=1,right=.95`，倒退得到`left=-1,right=-.95`；两者都减弱物理右侧。显式turn与stepping原样返回。此为开环命令差动，不是Yaw或足端反馈闭环。

## 0.8.8 前移命令的几何语义

`V10BodyPose::apply()`先假定零姿态下足端世界位置固定，再用机身姿态逆变换把足端写回新的机身坐标。Pitch=Roll=0时旋转矩阵退化为单位阵：

```text
world_x   = hip_x + nominal_forward - body_x
forward   = world_x - hip_x = nominal_forward - body_x
down      = nominal_down
```

因此默认`body_x=+8mm`使四腿的命令`forward`都相对名义值减8mm，`down`不变；在足端接触位置不动的物理解读下，机身向+X/机头方向平移8mm。之后仍在唯一的适配点调用`solve(-forward,down)`，所以没有新增或取消IK符号。它调整机身质量相对支撑足的前后杠杆，不是单独改变前腿高度。

显式测试覆盖零Pitch/Roll的四腿`nominal-8`和down不变；另用两组中位与前/后/左/右/踏步五种intent对Stand、Trot 16/13.1/0.5/down114和Walk 6/7.1/0.5/down108做完整周期预检，均通过。进一步重扫显示十种组合的保守共同连续边界为Trot约13.4477mm、Walk约7.49786mm；0.1mm档分别为13.4/7.4通过、13.5/7.5因`shank_map`拒绝。13.1/7.1不再称为+8下绝对最大。以上均是命令模型可达性，不是实物重心或足底载荷测量。

只有`V10ControlProfile`内置默认改成+8；通用`V10BodyPoseCommand{}`仍为0，便于纯变换和显式调用保持零偏置。Profile NVS解码会完整写回body_x，所以合法旧0或其他值继续覆盖；缺失、损坏或IO失败才使用+8。

0.8.7用真实`V10Gait::preflightAdvanced()`在`body_x=0`、两组中位`{90,100,90,90,90,97,90,102}`、`{95,100,85,80,100,80,85,100}`和前/后/左/右/踏步五种intent扫描：Trot（step16/down114）连续边界13.17996mm，13.1mm通过、13.2mm在phase 0.25腿1触发`shank_map`；普通Walk（step6/down108、CG关）连续边界7.17996mm，7.1mm通过、7.2mm在phase 0.10腿1触发`shank_map`。周期均为0.5s。这是0.8.7历史边界；0.8.8默认+8改变了足端径向距离，不能沿用为当前绝对边界。两版边界都只是软件模型，不等于带负载的实机安全认证。

## 0.8.6 速度语义

逆解、髋窗口、小腿映射、通道0..180°和支撑边距仍决定命令是否有效。软件不再由相邻命令角差推算峰值速度，也不会因周期、首段过渡、运行时帧、静态平衡或移动CG的命令变化率拒绝动作。舵机真实速度和能否跟随仍由硬件决定；1.5s smoothstep与各模式周期只是命令时间基准。

## 0.8.5 Trot坐标适配

原Py-Apple摆动输出x为0..S、z为0..H，支撑x从S匀速回0。当前足端接口以站姿为中心，因此只做：

```text
forward = stand_forward + signed_step * (original_x/S - 0.5)
down    = stand_down - lift * original_z/H
```

这保持总行程S和已存`stand_forward/body_x`含义，不引入第二次方向翻转；最终仍只在`V10Gait`的forward→局部IK入口调用`solve(-forward,down)`。Trot腿1/3与2/4错相0.5。Walk/CG仍走0.8.4分支。0.8.8启用的只是静态+8默认，不是原软件`in_y=17`或随`spd`叠加偏置的逐值移植；当前FF/IMU反馈仍默认关闭。

## 0.7.1 当前中位与左右方向

- `c_i`是每个物理通道的已标定名义命令角，来自RAM中位，启动时加载原NVS；它不是几何膝角。每次相对输出读取当前`c_i`，偏移0回中位，不修改标定。
- 腿1/4（左前/后）小腿`δs∈[-50,0]`，腿2/3（右前/后）`δs∈[0,+50]`。按现有接线表对应CH1/11与CH3/9。大腿机械限位未知，不照搬±50。
- 单路校准直接500–2500µs／名义0–180°，不再有135°限制或必须解锁；**电气范围不是机械安全范围**。相对命令越界或`c_i+δs`超绝对范围拒绝，不夹紧。原始校准脉宽允许绕过相对包络用于调零/排障。
- 竖直向下描述舵盘的机械零点，不能据此直接设膝折转幅值90°；新中位下的实际膝角和偏移→膝角曲线要重新测。`Ctrl/RelativeServoMap`只是中位加偏移→PWM，和二连杆IK/连杆映射是不同层。

## 二连杆 IK 输出什么

纯 `Ctrl/V10LegIk` 采用髋轴原点、局部 +X向照片右、+Y向下；输入显式上/下轴距和 `KneeFold`。输出 `hip_deg` 为上杆相对局部+X的角、`knee_turn_deg` 为上杆延长方向到下杆的**有符号折转**。图中的 θ₂ 是其幅值 `b=|knee_turn_deg|`：伸直0°、正交90°。膝关节两杆内夹角 `γ=180°−b`，不是 b；两者只在90°时相同。

```text
d² = x² + y²
c = (d² − l1² − l2²) / (2 l1 l2)
knee_turn = ±acos(c)
hip = atan2(y,x) − atan2(l2 sin(knee_turn), l1+l2 cos(knee_turn))
```

显式 `(80,61.357)` mm 的几何测试把 `(-61.357,+80)` 解回90°/90°并FK回代；另一折叠分支也可达相同足端，不等于当前腿形。其他三腿方向/镜像未确认，不能自动套用一条腿的分支。

## 历史旧中位的小腿候选：两姿态端点插值（不用于新标定）

按用户图片顺序暂以图1舵机90°、图2为51°。每图分别用髋轴 H、膝轴 K、脚端中心 F 的 `H→K` 与 `K→F` 方向差估膝折转变化，并用小腿固定球头安装臂 `K→B` 方向变化交叉核对：分别约 **21.3°** 和 **21.5°**。相机透视/取点仍有数度误差，不能把小数当精密实测；但这已经明确否定旧照片候选在51°只转约1.6°的预测。

以用户已调好的90°膝中位为锚，区间平均斜率约21.3/39=0.547，先圆整为 **0.55 膝折转度/舵机命令度**：

```text
折转幅值 b(s) ≈ 90 + 0.55(s−90)       51 ≤ s ≤ 90
舵机命令 s(b) ≈ 90 + (b−90)/0.55       68.55 ≤ b ≤ 90
膝内夹角 γ(s) = 180−b(s)
```

所以命令51°暂估折转幅值约69°、**膝内夹角约111°**；命令70°插值为折转79°、内夹角101°，这个中间点**尚未测过**。这是已被新中位三点数据取代的历史两点候选；当前`Ctrl/V10ShankLinearMap`接受显式单调节点表，不再把这组90/51数据作为活跃配置。

## 旧照片四杆为何退役，不共面怎么处理

旧单照片候选只估 S/K/A/B，在二维下把约60mm球心距当平面连杆长、为中位闭合微调 S。新实际动作是约21°输出变化，不符合旧预测；相应代码/测试已从活跃工程移除，[旧报告](../results/V10_photo_linkage_estimate_20260930.md)明确标为历史失败记录，可从 `.work/rejected-photo-fourbar-20260930.zip` 恢复。它算出的“非单调”或“51°无解”**不是实物结论**。

真实定长约束始终是三维 `|A(s)−B(knee)|=60mm`。若舵机/膝轴平行且球头只差恒定侧向高度 `Δz`，可严格降为二维，须用 `L_xy=sqrt(60²−Δz²)`；若轴不平行或错层随角变，需完整三维装配参数。照片投影57与实际60若**全由错层**导致，反算约18.7mm仅是示例，不是测得高差。当前两点经验映射不需要精确 S-K 来起步，实际连杆/装配影响已反映在观察到的端点动作里；但照片是投影，两点仍不能证明中间真实线性或安全。

## 0.8.0有符号步幅与CG目标

左侧腿1/4步幅`sL=step*(forward-turn)`，右侧腿2/3步幅`sR=step*(forward+turn)`，分别夹在±step内。前进正值时支撑足相对机身后移；踏步令`sL=sR=0`且stride bias为0，只保留lift。

CG Walk的前腿共同body_x目标为`F+min(0,sL/2)-margin`，后腿共同目标为`F+max(sR/2,(sL+sR)/2)+margin`。默认`+6/+6`退化为`F-2.5/F+8.5`；反向`-6/-6`为`F-5.5/F-0.5`；左转`-6/+6`为`F-5.5/F+5.5`；右转`+6/-6`为`F-2.5/F+2.5`。planner先以Profile的body slew到达目标容差，四足支撑且相位暂停，再开始摆腿。动态IMU修正作为独立±包络叠加到全局body_x，不改变几何或q表。

可选Trot前馈用左右signed stride计算等效平移`(sL+sR)/2/10`与转向`(sR-sL)/2/10`：正平移乘forward gain、负平移乘backward gain、零平移转向取正偏置乘turn gain，最后受max限制；踏步为0。它和移动IMU offset都只叠加到同一全局body_x；默认关闭时保留当前Trot kernel且body_x前馈为0。

运动请求本身0 PWM；后续新IMU样本先顺序写八路中位，再做1.5s smoothstep过渡。完整协调帧先校验后按八次I2C顺序写，非硬件原子；足端与角度遥测均为命令值而非反馈。NVS `applepycal/c{channel}`及中位编码未改，本轮未刷板、未发真实PWM。首次必须悬空、限流并备好物理断电。
